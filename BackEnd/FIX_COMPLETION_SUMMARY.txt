ROOT CAUSE YANG SUDAH DIIDENTIFIKASI:
═════════════════════════════════════════════════════════════════════════════

Original code hanya handle SVG (text-based), tidak ada logic untuk PNG/JPG
(binary format):

- SVG = Text XML → bisa read sebagai UTF-8 → encode langsung
- PNG/JPG = Binary bytes → harus read as Buffer → encode to base64

Solution: Tambah imageToDataUrl() untuk binary image + assetToDataUrl() 
untuk auto-detection format.

TECHNICAL EXPLANATION:
═════════════════════════════════════════════════════════════════════════════

Why SVG worked but PNG/JPG didn't:

SVG (Text-based XML):
  ✓ Read as UTF-8 text: fs.readFileSync(file, 'utf8')
  ✓ Direct encode to data URL: data:image/svg+xml;utf8,...
  ✓ Browser renders correctly

PNG/JPG (Binary format):
  ✗ Read as UTF-8 text = garbage/corrupted data
  ✗ Encode corrupted data = invalid data URL
  ✗ Browser can't decode invalid data URL
  ✗ Image missing/broken in PDF

Solution: Binary image → base64 encoding

PNG/JPG (Binary format) - FIXED:
  ✓ Read as binary Buffer: fs.readFileSync(file)
  ✓ Encode to base64: buffer.toString('base64')
  ✓ Data URL: data:image/png;base64,{base64String}
  ✓ Browser decodes base64 → renders correctly
